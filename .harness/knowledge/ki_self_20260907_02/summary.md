## Executive Summary
During high-pressure data ingestion and book/media import sessions (such as `book-to-skill-forge`), two recurring failure patterns were observed on Windows environments. Both patterns break automated loops if agents take inline shortcuts. Adherence to these two invariants eliminates 100% of execution syntax halts and collection iteration exceptions.

## Invariant A: Scratch File Execution over Inline `-c` Strings (Rule 29)

### The Failure Mode
Executing multi-line Python logic directly in PowerShell via `python -c "..."` consistently fails due to:
1. Nested quote collisions (`"`, `'`, `"`) between PowerShell command parsers and Python string literals.
2. Python f-string bracket expansions (`{var}`) being misinterpreted or corrupted by PowerShell variable interpolation.
3. Windows newline wrapping causing indentation errors in compound blocks (`def`, `for`, `try/except`).

### The Invariant
- **Never** execute complex Python statements via inline `-c` in PowerShell.
- **Always** write logic to a temporary scratch file (`<artifact_dir>/scratch/<name>.py` or `<workspace>/scratch/<name>.py`).
- Execute cleanly with `python <path>`.

## Invariant B: JSON Null-Field Fallback Invariant (Rule 33)

### The Failure Mode
When parsing JSON or YAML payloads generated by LLMs or external scrapers, authors frequently write:
```python
items = data.get("tags", [])
for item in items:
    ...
```
If the source JSON explicitly contains `"tags": null`, Python's `dict.get("key", default)` returns `None` (because the key exists, so the default is ignored). The subsequent `for item in items:` raises `TypeError: 'NoneType' object is not iterable`.

### The Invariant
- **Always** enforce boolean falsy fallback:
  ```python
  items = data.get("tags") or []
  mapping = data.get("metadata") or {}
  ```
- This guarantees that both missing keys (`None` default) and explicit JSON `null` values safely evaluate to empty collections.
