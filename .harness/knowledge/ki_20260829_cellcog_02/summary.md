# KI: Pure Copy Multi-Channel Skill Distribution & Drift-Proof Catalogs

## Operational Summary
Distributing a large catalog of agent skills across multiple package ecosystems (e.g. `npx skills`, OpenClaw ClawHub, IDE plugins, and manual imports) often leads to documentation drift, channel-specific forks, and broken links. Adopting a **pure copy + validation** model with single-source golden copies and automated markdown table injection eliminates documentation staleness and synchronization friction.

## Architecture Invariants

1. **Golden Copy Single Source**:
   - Golden skill definitions live in a monorepo (e.g. `openclaw_skills/`).
   - The public distribution repository (e.g. `skills-main/`) is strictly a build artifact generated by `scripts/sync_skills.py --execute`.
   - *Rule*: Never edit skills in the build output directory; always edit the golden copy.

2. **Universal Markdown Format (No Content Transformation)**:
   - SKILL.md files carry multi-channel install instructions (npx, OpenClaw, IDE plugin, manual).
   - Readers and agents self-select their appropriate install channel.
   - Syncing is a pure copy with zero regex transformations or channel-specific mangling.

3. **Strict Naming & CI Invariants**:
   - `folder_name == frontmatter.name == ClawHub_slug`.
   - `scripts/sync_skills.py --check` runs in CI pipelines and exits `1` upon any detected file drift or missing description.

4. **Drift-Proof Markdown Catalog Tables**:
   - The root README catalog table is dynamically generated between explicit comment markers (`<!-- CATALOG:START -->` ... `<!-- CATALOG:END -->`) directly from parsed frontmatter metadata.
