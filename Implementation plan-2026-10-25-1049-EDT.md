## How to use this plan

- Every item is a checkbox. Pick items off in any order, but the suggested sequence in §1 is the recommended one.
- **P0** = do first (security hole, or the core learning loop). **P1** = high leverage, do soon. **P2** = valuable, do when convenient. **Verify** = finding was blocked by GitHub rate limits during analysis and needs a re-read before acting.
- Evidence paths are given for every item so you can check the claim before starting.
- JSON, schemas, and structured data are inline as code blocks, per repo convention for handoff documents.

## 1. Suggested sequence

1. **Track 0 — Security ( §3 ).** One archive-hardening fix (Zip Slip in the fetcher and loader, now done) plus a few fail-open behaviors. These are small, independent, and should land before anything else that touches ingestion.
2. **Track 1 — The learning core ( §4, §5 ).** Self-reflection + knowledge graph. This is the most important part of the project: the epistemology (how the harness knows) and the ontology (how things relate). The single biggest gap in the whole repo is that the vault is currently write-only — reflection writes knowledge items, but nothing in the agent loop reads them back.
3. **Track 2 — Consolidation ( §6, §7 ).** The codebase has grown by deepening, and deepening has left seams: three DAG models, three plugin-handling layers, eleven bridge implementations, ~70 CLI names for ~45 groups. None of these are crises; all of them compound.
4. **Track 3 — Interfaces, tests, docs, skills ( §8, §9, §10 ).** CLI/UI drift, test-layout drift, doc drift, and skill-catalog hygiene.

## 3. Track 0 — Security: the ingestion trust boundary

Ingestion is *designed* to consume untrusted foreign code, so its trust boundary is the project's most security-sensitive surface. These items are small and independent.

- [x] **P0 — Fix Zip Slip in the fetcher.** Done 2026-10-25 (commit `ef98eab`). Correction to the original framing, verified empirically: CPython's `zipfile.extractall` already sanitizes classic `../` traversal (files land inside the target, not outside it), so this was hardening, not an open escape. The fix adds a shared `validate_zip_members` in `src/harness/plugins/loader.py`, wired into both `RepoFetcher._extract_zip` and `PluginLoader.load_from_zip` (the plan originally named only the fetcher; the loader had the same call), rejecting `..`, absolute/drive paths, backslash traversal, and symlink members with a loud error instead of silent rewriting — plus 4 regression tests that fail on the old code and pass on the new.
- [x] **P0 — Bound fetched content.** Done 2026-10-25. Added streaming download helper (`_download_zip_streaming`) reading in chunks with byte-accumulation limits (`max_download_bytes`, default 100 MB). Extended `validate_zip_members` in `src/harness/plugins/loader.py` to enforce member count limits (`max_files`, default 10,000), total uncompressed byte limits (`max_total_bytes`, default 250 MB), and suspicious compression ratio checks (>100:1 for members >1 MB). Replaced the full recursive directory walk in `_extract_zip` with $O(1)$ member counts from zip archive info.
- [x] **P0 — Fix cache-key collisions.** Done 2026-10-25. Remote ZIPs are keyed by URL SHA-256 hash (`stem__<sha256[:12]>`) and local ZIPs by path/size/mtime SHA-256 hash (`stem__<sha256[:12]>`). Extracted directories write a `.cache_meta.json` record containing source, hash, ref, stem, and timestamp. Added `_is_cache_valid` checking provenance, automatically invalidating stale caches on source/hash/ref mismatch or `force=True`. Added `derive_plugin_name` to cleanly resolve logical plugin stems from hashed directories.
- [x] **P1 — Make the PyPI converter fail loudly.** Done 2026-10-25. Raised `PyPIFetchError` in `src/harness/ingestion/pypi_converter.py` on 404 and HTTP/network failures instead of fabricating fake `1.0.0` metadata. Exported in `src/harness/ingestion/__init__.py`. Added comprehensive unit test contract in `tests/test_universal_ingestion.py`.
- [x] **P1 — State and enforce the isolation mode of dynamic plugins.** Done 2026-10-25. Documented in-process compilation isolation constraint in `DynamicPluginBuilder.from_code`, enforced `trusted: bool = True` requirement (raising `ValueError` if `trusted=False`), added explicit `isolation = IsolationMode.IN_PROCESS` property on `DynamicPythonPlugin`, and verified in `tests/test_creator_dynamic_decomposition.py` that untrusted requests are rejected and demoted to `SubprocessExecutor` by `SandboxExecutorFactory`.
- [x] **P1 — Pin or sandbox bridged peer code.** Done 2026-10-25. Added strict `test_memtext_interface_conformance` in `tests/test_memtext_bridge.py` asserting that fallback/local `LocalMemtextService` matches the complete method signature, parameter typing, and return type contracts of `MemtextService`.
- [x] **P1 — Audit WASM and container executor defaults.** Done 2026-10-25. Audited WASM (`wasm.py` uses `wasmtime.WasiConfig()` with zero filesystem/network capability grants by default). Hardened container executor in `container.py` by adding `--security-opt=no-new-privileges` and `--cap-drop=ALL` alongside existing `--network=none`, `--read-only`, and `-v <dir>:/app:ro`.
- [x] **P2 — Remove the async/sync footgun in the validator.** Done 2026-10-25. Implemented `DualModeValidationReport(ValidationReport)` in `src/harness/creator/validator/engine.py`, which is both an `Awaitable` coroutine proxy and a slotted synchronous proxy. Calling `PluginValidator.validate(...)` or `ValidationFixer.remediate(...)` can now be directly awaited (`await PluginValidator.validate(...)`) in async contexts or accessed directly (`report = PluginValidator.validate(...)`, `assert report.valid`) in synchronous contexts without raising unawaited-coroutine errors, while preserving `validate_sync(...)` compatibility. Tested in `tests/test_creator_validator_decomposition.py`.
