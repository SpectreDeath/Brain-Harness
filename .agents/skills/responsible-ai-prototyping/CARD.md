## The 5-Stage Responsible Prototyping Loop

| Stage | Objective | Primary Artifact / Output | Completion Gate |
|---|---|---|---|
| **1. Intent & Minimization** | Frame problem scope, strip unneeded PII, isolate secrets to `.env` | Data minimization inventory | Zero unneeded PII fields; secrets isolated |
| **2. Security-First Prompts** | Construct prompts using Responsible Prompt Template with constraints | Structured feature prompt | Acceptance criteria & negative bounds defined |
| **3. Auth/Authz Testing** | Execute 5 negative security tests; assert server-side enforcement | Auth test execution matrix | 5/5 negative auth/authz tests pass (401/403) |
| **4. Code & a11y Hardening** | Prune souvenir packages, sanitize inputs/errors, verify WCAG contrast | Hardened codebase & deps | Bloat removed, logs clean, dark patterns purged |
| **5. Stage-Gate Readiness** | Run recursive AI self-reviews, Golden Rule check, label prototype | Readiness assessment report | Empathy audit passed; honest stage labeling |

## The Three Pillars Cheat Sheet

### 1. The Responsible Prompt Template
```markdown
Build [feature] for [type of user] to [solve problem].
Users should be able to: [action 1], [action 2].
The application MUST:
- Validate all input client & server-side.
- Enforce server-side authorization on private routes.
- Isolate secrets to environment variables.
- Support keyboard navigation & WCAG AA contrast.
Do NOT: collect unnecessary data, expose private IDs, or alter auth unannounced.
Explain: modified files, data schemas, external APIs, residual risks, test steps.
```

### 2. The 5 Negative Auth/Authz Tests
1. **Logged-out route access**: Access `/admin` $\rightarrow$ must redirect / 401.
2. **Role escalation**: Standard user hits admin endpoint $\rightarrow$ must return 403.
3. **Horizontal IDOR**: User A swaps URL ID to User B's record $\rightarrow$ server rejects access.
4. **Stripped session**: Request without auth header $\rightarrow$ server rejects mutation.
5. **Post-logout cache**: Logout and press browser back button $\rightarrow$ no private data shown.

### 3. Explicit Anti-Patterns Box
- **Client-Side Security Illusion**: Hiding buttons or UI routes while leaving backend APIs open.
- **Digital Souvenir Hoarding**: Accumulating heavy npm packages for small UI widgets.
- **Production Pretending**: Calling an experimental prototype launch-ready due to pretty gradients.
- **Silent Secret Ingestion**: Pasting live credentials or tokens into generation prompts or client bundles.
- **Unverified AI Self-Review**: Trusting an AI model's assertion that its code is secure without manual tests.
- **Dark Pattern Manipulation**: Pre-checked marketing checkboxes or deceptive cancellation workflows.
