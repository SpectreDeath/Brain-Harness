## 3. Cross-Phase Empirical Interactions Surfaced in Phase 9

Three honest benchmark shifts appeared when re-running the full pipeline end-to-end after all 8 improvements landed—none are regressions, and each validates live fidelity:

1. **Uncapped self-scan revealed core SCC edges & Track 3 cleanup (`Phase 7 -> Phase 9 -> Track 3`):** Switching `brain_harness_src` in `p00_snapshot.py` and `p00_roundtrip_check.py` to `max_files_per_unit=None` scanned all `421` Python files in `src/harness/services/` (instead of stopping at 60), uncovering real edges (`services -> creator`, `services -> events`, `services -> ingestion`; `55 -> 58` total edges at Phase 9). On `2026-11-19` (Track 3), moving `ReflectionDaemonWorker` into `src/harness/creator/reflection/worker.py` eliminated `services -> creator -> services` (`58 -> 57` edges) and removed `ALLOWED_SERVICES_TO_CREATOR`. Re-running `validate_model` now surfaces `spider_cycle_violations: ["services -> plugins -> services"]` inside the 6-unit core Tarjan SCC (`["creator", "events", "ingestion", "kernel", "plugins", "services"]`; `kernel`/`events`/`plugins`/`creator`/`ingestion`/`services` core coupling documented as a known architectural limitation while `6/12` outer packages remain acyclic; [results/p09/refactor_order.json](results/p09/refactor_order.json), [results/p09/summary.md](results/p09/summary.md)).
2. **New Phase 6 `smart_eval` edge vs frozen Phase 6 gold key (`Phase 6 -> Phase 9`):** Because `ki_google_research_smart_eval` carries a valid `references_code -> harness.services.uncertainty_guard` edge added in Phase 6 after the 4-KI static gold answer key was frozen in Phase 1, `uncertainty_guard` `hop0` precision shifted from `1.00` (`4/4`) to `0.80` (`4/5`), bringing macro `hop0` P/R/F1 from `1.0000/1.0000/1.0000` to `0.9600/1.0000/0.9778` (still well above baseline `0.4000/0.2500/0.2800` and `grep_baseline` `0.8769` F1; [results/p06/summary.md](results/p06/summary.md)).
3. **Live Phase 5 verification vs static Phase 11 disputes (`Phase 5 -> Phase 9`):** In Phase 2, `p11_grounded_voting.py` scored `11/12` (`91.7%`) because `ki_njoku_uncertainty_aware_systems` was `UNVERIFIED` (`0.6x`). After Phase 5 genuinely verified `ki_njoku_uncertainty_aware_systems` (`1.0x`) against live workspace SHA-256 hashes, Disputes #2 and #4 no longer penalized its vote pluralities against competing verified KIs, yielding `9/12` (`75.0%` vs `16.7%` raw, `7` flips toward correct, `0` toward wrong; [results/p11/summary.md](results/p11/summary.md)).
